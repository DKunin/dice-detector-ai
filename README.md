# dice-detector-ai

Сервис проверяет готовые 400px-превью PhotoKun через OpenAI Decisions API (`gpt-6-luna`) и добавляет тег `dice` только при консервативном совпадении. Весь трафик OpenAI идет через обязательный SOCKS5-прокси.

## Как работает

- при старте выполняет полный проход от новых фотографий к старым;
- одновременно отправляет не больше `CONCURRENCY` изображений (по умолчанию 4);
- сохраняет checkpoint по `entry_id`, версии превью и версии детектора в отдельной SQLite;
- после полного прохода раз в `POLL_INTERVAL_MS` ищет новые или изменившиеся превью;
- использует две независимые вероятности: наличие настоящих игровых кубиков и наличие только похожих объектов;
- повторно проверяет каждый положительный результат отдельным запросом и ставит тег только при полном согласии;
- добавляет тег идемпотентно через `INSERT OR IGNORE`, а checkpoint пишет только после успешной записи PhotoKun;
- не удаляет пользовательские теги и не отправляет исходные фото — только локальные WebP-превью.

Состояние доступно в `data/status.json`. Ошибки 429/5xx и сетевые сбои повторяются с экспоненциальной задержкой. Неисправимые ответы сохраняются в checkpoint, чтобы не тратить деньги бесконечно на один файл.

## Локальный запуск

```bash
cp .env.example .env
# заполнить OPENAI_API_KEY, SOCKS5_PROXY и TARGET_AUTH_SUBJECT
npm ci
npm test
npm run build
npm start
```

Для безопасной проверки без записи тегов:

```bash
DRY_RUN=true RUN_ONCE=true SCAN_LIMIT=5 npm start
```

`ENTRY_IDS=id1,id2` ограничивает пробный запуск конкретными PhotoKun ID. В dry-run checkpoint тоже не сохраняется, поэтому последующий рабочий запуск проверит файлы заново.

## Развертывание

Скопировать проект в `/var/apps/dice-detector-ai`, создать `.env`, затем:

```bash
mkdir -p data
docker compose build
docker compose up -d
docker compose logs -f --tail=100
```

Compose монтирует PhotoKun SQLite с правом записи только для добавления тегов, каталог превью — только для чтения, а собственные checkpoint/status — в `./data`. Контейнер автоматически перезапускается через `restart: unless-stopped`.

Контейнер запускается с UID 0, потому что production SQLite PhotoKun принадлежит root. В контейнер не передается Docker socket, каталог превью смонтирован read-only, а доступ на запись ограничен каталогом данных PhotoKun и собственным `./data`.

Основные настройки описаны в `.env.example`. Повышение порога меняет вычисляемую версию детектора и запускает повторную проверку. Для ручного контроля версии можно задать `DETECTOR_VERSION`.

## Стоимость и приватность

Decisions API оплачивается только по входным токенам. Использование небольших готовых превью, одного основного запроса на фото и второго запроса только для предварительно положительных результатов минимизирует стоимость. Превью отправляются OpenAI как inline base64; URL или оригиналы PhotoKun не передаются.
